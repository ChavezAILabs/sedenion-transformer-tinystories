## Architecture — the validation chain

The codebase is a chain of increasingly integrated layers, each validated against the one before it. Math flows one direction only:

1. **`sedenion_kernel.py`** (NumPy, ground truth) — Cayley-Dickson structure tensor (Baez convention), exhaustive zero-divisor search (336 annihilating pairs), collapse identity `(aP+bQ)(bP+cQ) = −2b(a+c)e₀`.
2. **`test_zda_numpy.py`** (NumPy mirror) — re-derives every piece of math used in the torch layers (PHM semantics, gate↔identity equivalence, β=0 equality, causality, RoPE) without torch.
3. **`zda_layers.py`** (PyTorch) — `PHMLinear` (PHM-16) and `ZDGatedCausalSelfAttention` (standard causal MHA + RoPE + additive ZD gate `logits −= β·|a_i + c_j|`), with embedded tests T1–T7.
4. **`model.py` / `data.py` / `train.py` / `configs/`** — nanoGPT-style smoke harness. `ZDAModel` selects variants via `VARIANT_ATTN_KWARGS` (B0/B1 dense, V1 phm16, V2 zd-gate, V3 random-frame gate control, V4 shuffled-tensor structure control). `ZDABlock` is a copy of `zda_layers.Block` with configurable MLP width (documented deviation, needed for param matching); the attention module is used unmodified.
5. **`zda_grid.py`** — self-contained Phase-3 script for Colab/Kaggle (18 runs, TinyStories, resumable checkpoints). Its Section 1 is a **verbatim copy** of the validated `zda_layers.py` code — never edit it directly; change `zda_layers.py` + `test_zda_numpy.py` first, then re-copy.

If a torch test fails, the NumPy mirror is ground truth: diagnose whether it's plumbing (dtype/device/shape) or math, and fix the torch port, not the math.

Phase 4 is a **parallel, successor chain** using the same validate-each-layer-against-the-one-before pattern, not an extension of the chain above (the kernel itself changed, so nothing downstream of `sedenion_kernel.py` carries over unmodified): `verify_phase4_memo.py`/`phase4_positional.py`/`phase4_shuffledT_nulls.py` (repo-verify the design memo's claims) → `test_phase4_numpy.py` (NumPy mirror, P4M1–M7) → `phase4_layers.py` (`K3Attention`, P4T1–T8) → `phase4_model.py` + `phase4_train.py` (variant grid D0p/D0/D1/S/X/Q0) → `dial_data.py` (the graded task, v2) → `phase4_grid.py` (the 18-run anchor-grid orchestrator, Phase 4's analogue of `zda_grid.py`). One deliberate deviation from the `zda_grid.py` pattern: `phase4_grid.py` **imports** `phase4_layers`/`phase4_model` rather than bundling a verbatim copy (no re-copy step to maintain; Colab runs upload all three files). `phase4_v1_prediction.py` is a one-off script that reroutes `dial_data.gen` to the archived leaky v1 generator for a single prediction test — not part of the validation chain.

## Invariants — do not break

- **β=0 ≡ baseline:** β initializes to 0 so V2 is *exactly* standard attention at init. Enforced by test T4 and a step-0 regression assert in `train.py` (V2 loss == B0 loss to 1e-5 on an identical batch/seed). β is deliberately unconstrained (no softplus/β²) so the gradient is live at init, and its learned sign is a diagnostic (positive = suppress annihilation-aligned pairs, negative = amplify). A "sign-flipped gate" (`+β|a+c|`) is the same model family reparameterized — never add it as a separate variant.
- **β must not be weight-decayed** — `make_optimizer` decays only ≥2-D params; decaying β would force the gate off by fiat.
- Never loosen a test tolerance beyond 1e-5 or weaken an invariant (especially T4 β=0 equality and T6 causality) to make a test pass.
- **Reproducibility:** data order is seeded independently of model RNG so all variants at a seed see identical batches; eval batches are seeded by (seed, step). Anything that consumes RNG differently per variant breaks cross-variant comparability. The grid requires the same `batch_size` across all runs.
- **Matching targets:** params within ±1% of B0, FLOPs within ±5% (B1 vs V1). Configs' `d_model`/`mlp_hidden` are tuned to hit these; verify with `model.py` after config changes.
- **Controls V3/V4 are non-negotiable** — they're what makes any positive result attributable to zero-divisor structure specifically.
- Sedenion convention is **Baez**: `(a,b)(c,d) = (ac − d̄b, da + bc̄)`. The ZD_PAIR constant (e3+e12, e5+e10) — KSJ "Pattern 2", adopted pre-Phase-3 over the original (e1+e10, e4−e15); deviation logged in `RESULTS_phase2_smoke.md` §6 — is valid only in this convention. If another tool disagrees, flag the convention mismatch, don't average over it. This pair also independently appears in Reggiani's (arXiv:2411.18881) published table and in the owner's separate Canonical Six paper's E₈ Weyl-orbit result — see `LIE_ALGEBRA_CONNECTIONS.md` for the full cross-reference; don't confuse that E₈ (the exceptional Lie group) with `phase4_positional.py`'s "e8" (just the 8th Cayley-Dickson basis vector).
- Pre-registered decision rules live in spec §1; do not reinterpret them after results exist. Negative results get written up with the same care as positive ones.

## Phase 4 invariants — do not break

- **K3 is mandatory, not gated** — unlike V2's β=0≡baseline anchor, K3 always contributes to the score; there is no init-time equivalence to standard attention to regression-test against. The replacement anchors are: the structural-null test on the 336-pair table, the K1-degeneracy guard (live raw-score row spread, must stay > 0 in training), the P4T8/octonion-degeneracy end-to-end test, causality, and NumPy-mirror-first. Don't try to resurrect a β=0-style baseline-equivalence test for K3 — it's a different model family by design.
- **Never build K1** (linear collapse score `−2b(a_i+c_j)`) — additively separable, makes attention query-independent regardless of parameters. This is a closed door (memo, repo-verified), not a design choice to revisit.
- **Positional action is `R_8(θ) = cosθ·I + sinθ·L_8`, uniquely** — `phase4_positional.py` proves the other 14 basis generators fail the relative-position property or cross the annihilation manifold. Per-head single-frequency `R_8(ω_h·pos)` is required; within-head multi-frequency fails relative-position. The ladder itself is frozen at v1.0: ω_h = (2π/1024)^(h/(H−1)) — single source of truth is `phase4_layers.frozen_omega_ladder()`, exposed as the `omega_h` buffer that `phase4_grid.py` preflight [P4] verifies (identical for S/X and D0p/D1 by construction).
- **Score path must be fp32 end-to-end, TF32 off for the product op** — fp16 storage quantizes near-manifold distance to a floor (~1e-3 originally estimated, ε=1e-4 confirmed on GPU 2026-07-21) and kills the gradient there; casting up after quantization doesn't recover it. bf16 does **not** reproduce this floor down to ε=1e-5 (confirmed on CPU and GPU 2026-07-21, `phase4_gpu_tf32_confirm.py` — supersedes an earlier informal "~1e-2, unusable" estimate that was never captured in a rerunnable script). **GPU confirmed 2026-07-21** (Tesla T4): TF32-off is faithful to ε=1e-5; TF32-on gave bit-identical results at this shape, so whether this contraction ever actually routes through TF32 tensor cores at Phase 4 sizes is unconfirmed either way — the guard (`phase4_train.py`, added this session — was previously entirely absent) is kept regardless since it's free at these dims.
- **Variant R (random-frame K3) is dropped, not a null result to re-add** — orthogonal conjugation of the multiplication is exactly absorbed by learned full-rank projections (`score_R(q,k;W) ≡ score_S(q,k;OW)`, verified to 1e-10). Specificity now comes from X (shuffled-tensor) + Q0 (query-independent) + the octonion theorem, not from an R arm.
- **Shuffled-tensor (X) draws are valid controls but not null-matched** — they have 66–96 exact two-blade null pairs (seed-dependent) vs. the true tensor's 336, and are diffusely near-singular (~12× closer to singular generically). Don't interpret X as "no ZD structure"; it's "different, denser ZD-like structure." `phase4_shuffledT_nulls.py` is the seed-by-seed characterization — check it before trusting a new seed.
- **Dial task is v2 (balanced collisions); v1 is archived as leaky, not deleted** — v1's prefix-only collisions let a suffix-only heuristic solve it (score rising with δ, the opposite of the intended difficulty dial). Never use `dial_selective_recall_prototype_v1_LEAKY.py` as a data source except through `phase4_v1_prediction.py`'s explicit, documented reroute for the one prediction test it exists to run.
- **γ (K3's per-head scale param) is never weight-decayed**, same rule and same reason as β in Phase 1–3: it's 1-D, and decaying it would suppress the kernel's contribution by fiat rather than by what SGD learns.
